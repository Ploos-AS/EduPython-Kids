# Vocabulary and terminology

This document keeps the Norwegian beginner vocabulary consistent.

| Python / concept | Preferred Norwegian wording | Notes |
| --- | --- | --- |
| variable | variabel | A value the program can remember/change |
| input | input / svar fra brukeren | Keep Python function name `input()` as code |
| output | det programmet skriver / resultat | Avoid requiring the term «output» early |
| condition | betingelse | Explain as a question that is true or false |
| loop | løkke | Use `for`-løkke and `while`-løkke |
| function | funksjon | Early explanation: «en navngitt oppgave vi kan bruke igjen» |
| parameter | parameter | Introduce only when functions need flexible input |
| return value | returverdi / verdien funksjonen sender tilbake | Prefer plain-language explanation first |
| list | liste | Collection of values |
| index | indeks / plass i listen | Explicitly explain that Python starts at 0 |
| random | tilfeldig | `random` remains the module name |
| bug | bug / feil | Treat as normal debugging work |
| debugging | debugging / feilsøking | Both may appear; explain the first time |
| game state | spilltilstand | Use mainly in adult material |
| scope (project) | omfang | Adult/project-planning term, not required vocabulary for children |

## Style rules

- Use short sentences and concrete examples in student material.
- Keep Python keywords and function names in code formatting.
- Prefer «programmet» over anthropomorphic claims that the computer actually thinks or knows.
- Use «Hva tror du skjer ...?» consistently for prediction.
- Introduce at most one or two major new ideas per lesson.
- Do not require memorisation of syntax.
- Treat error messages as information.
- Use fictional data whenever real personal information is unnecessary.
- Keep advanced terminology in teacher material until it becomes useful to the student.
