# Tilgjengelighetsveiledning

**Omfang:** Python Explorer M2-klasseromsmateriale  
**Sist gjennomgått:** 2026-09-25

EduPython Kids skal kunne brukes av så mange elever som praktisk mulig uten å kreve én bestemt måte å lese, skrive, se, høre eller gjennomføre en oppgave på. Tilgjengelighet er et løpende designkrav, ikke en engangssertifisering.

## Prinsipper

### Ikke avhengig av farge eller emoji
Kursinnholdets mening skal ikke avhenge av farge. Ikoner som 🎯, 💻, 🔧 og 🐞 har alltid tekstetiketter. Utskriftsmaterialet skal fungere i svart-hvitt.

### Konkret språk og lav minnebelastning
Bruk korte setninger, konkrete eksempler og høyst én eller to store nye ideer per leksjon. Eleven skal kunne starte med fungerende kode og eksperimentere uten å memorere syntaks.

### Ulike lese- og arbeidshastigheter
Pacing-planene er veiledende, ikke tidsfrister. Frivillige utfordringer kan hoppes over eller fortsettes senere. Hastighet skal ikke brukes som mål på læring.

### Skriving og motorikk
Skrivehastighet er ikke læringsmålet. Voksne kan gi starterfiler, skrive kode eleven dikterer, tillate kopiering fra eksempler, bruke alternative inndataenheter og dele prosjektet over flere økter. Eleven bør fortsatt ta meningsfulle programmeringsvalg.

### Tastatur, skjermleser og zoom
Tekstleksjonene kan gjennomføres tastaturbasert i en egnet editor/terminal. Markdown bruker overskrifter, lister, kodeblokker og vanlige lenker. Python-kode kan være krevende med skjermleser fordi tegnsetting og innrykk har betydning; editor og hjelpemidler må derfor testes i det faktiske miljøet.

Tekst bør kunne forstørres uten at innholdet mister mening. Fremtidig web/PDF-layout skal tåle høy zoom og smale visninger.

### Ingen lyd- eller tidspress
Ingen nåværende leksjon krever lyd. Det finnes ingen tidsbegrensede programmeringsoppgaver.

### Feil og emosjonell belastning
Feil behandles som informasjon. Unngå merkelapper som «flink», «dårlig», «treg» eller «svak». Ved problemer: les feilen, finn linjen, test én liten del, endre én ting, kjør igjen.

### Personvern
Oppgaver skal ikke kreve ekte navn, adresse, skole, passord eller andre unødvendige personopplysninger. Bruk oppdiktede figurer, kallenavn og fiktive data.

## Sjekkliste før undervisning
- [ ] Eleven kan lese eller på annen måte få tilgang til leksjonsteksten.
- [ ] Teksten i editoren kan forstørres.
- [ ] Tastatur eller alternativ inndatametode fungerer.
- [ ] Terminalutdata er tilgjengelig.
- [ ] Nødvendige hjelpemidler fungerer med valgt editor.
- [ ] Starterfiler finnes hvis skriving er en barriere.
- [ ] Ingen aktivitet avhenger av bare farge eller lyd.
- [ ] Det er nok tid uten hastighetspress.
- [ ] Turtle/Tk er testet før grafiske leksjoner.

## Kjente risikoer
De viktigste gjenstående risikoene er miljøavhengige: skjermleser/editor, Python-innrykk med hjelpemidler, Turtle/Tk på klasseromsmaskiner og framtidig web/PDF-layout.

**Resultat: M2 kildekode-/innholdsnivå tilgjengelighetsgjennomgang PASS.**

Dette er ikke en påstand om formell WCAG-samsvar eller kvalifisering av alle operativsystemer, editorer og hjelpemidler.
