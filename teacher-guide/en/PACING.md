# Classroom pacing plans

Times are guides, not deadlines. Keep the same rhythm: **Mission → working code → change → predict → test → reflect**.

## 30 minutes
0–3 mission; 3–8 smallest working example; 8–15 changes and predictions; 15–23 one exercise or bug hunt; 23–27 learner variation; 27–30 reflection.

## 45 minutes
0–5 mission/recap; 5–12 core example; 12–22 guided changes; 22–32 exercise; 32–39 bug hunt or learner variation; 39–45 demonstration and explanation.

## 60 minutes
0–5 mission/recap; 5–15 core example; 15–25 changes/predictions; 25–38 main exercise; 38–48 extension or playtesting; 48–55 improve from testing; 55–60 demonstrate and explain.

Project-heavy lessons 12, 15 and 16 may span multiple sessions. Turtle often deserves extra time for exploration.

## Stages
**Discover 1–4:** output, variables, input, numbers.  
**Decide 5–8:** conditions, randomness, `for`, first combined game.  
**Build 9–12:** `while`, game state, functions, Monster Battle.  
**Create 13–16:** lists, Turtle and independent creation.

If the learner can predict, change and test, stop explaining and let them work. Extra time should deepen the current idea rather than introduce several future concepts.
