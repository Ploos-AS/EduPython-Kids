# Classroom pacing plans

These plans help an adult run Python Explorer lessons in different time windows without rushing the learner.

The times are guides, not deadlines. A learner who is experimenting productively is already doing the work.

## Core principle

Keep the same learning rhythm at every session length:

**Mission → working code → change something → predict → test → reflect**

Do not try to fit every optional challenge into one session. It is better to finish with curiosity than to hurry through extra material.

## 30-minute session

A short session should have one clear learning goal.

| Time | Activity |
| --- | --- |
| 0–3 min | Introduce the mission. Show what the learner will make. |
| 3–8 min | Type or open the smallest working example. Run it early. |
| 8–15 min | Change values, text or one small rule. Predict before running. |
| 15–23 min | Do one core exercise or bug hunt. |
| 23–27 min | Let the learner make one personal or fictional variation. |
| 27–30 min | Ask what changed, what surprised them and what they would try next. |

For project-heavy lessons such as 12, 15 and 16, use several 30-minute sessions rather than compressing the project.

## 45-minute session

This is the recommended default for many classroom or club settings.

| Time | Activity |
| --- | --- |
| 0–5 min | Mission and quick recap of one previous idea. |
| 5–12 min | Build and run the core example. |
| 12–22 min | Guided changes and prediction questions. |
| 22–32 min | Core exercise or challenge. |
| 32–39 min | Bug hunt, testing or learner-designed variation. |
| 39–45 min | Show the result and explain one piece of code. |

If the learner gets deeply interested in a variation, let that replace an optional exercise.

## 60-minute session

A longer session gives room for experimentation and debugging.

| Time | Activity |
| --- | --- |
| 0–5 min | Mission and recap. |
| 5–15 min | Build and run the core example. |
| 15–25 min | Change the program and make predictions. |
| 25–38 min | Main exercise or challenge. |
| 38–48 min | Learner-designed extension, bug hunt or playtesting. |
| 48–55 min | Improve one thing based on testing. |
| 55–60 min | Demonstrate and explain what was learned. |

Include a short movement break when useful, especially if learners are sharing computers or a session contains a lot of typing.

## Suggested lesson grouping

### Stage 1 — Discover

Lessons 1–4 introduce output, variables, input and numbers.

For beginners, prefer one lesson per session. Lessons 1 and 2 can sometimes share a 60-minute session if the learner is comfortable typing and experimenting.

### Stage 2 — Decide

Lessons 5–8 introduce decisions, randomness, `for` loops and the first combined game.

Lesson 8 benefits from its own session so the learner has time to combine earlier ideas.

### Stage 3 — Build

Lessons 9–12 introduce `while`, game state, functions and Monster Battle.

Do not rush lessons 11–12. Understanding why a function exists is more important than memorising `def` syntax.

Monster Battle can use two sessions:

1. understand and run the base game
2. modify, test and balance the learner's version

### Stage 4 — Create

Lessons 13–16 introduce lists, Turtle and independent creation.

Turtle lessons often need extra time because learners naturally experiment with shapes and designs.

A useful project schedule is:

- lesson 15: build and reuse drawing components
- lesson 16A: idea and minimum working version
- lesson 16B: test and improve
- lesson 16C: demonstration and reflection

## When to stop explaining

If the learner can predict, change and test the program, let them work.

Useful adult prompts include:

- What do you think will happen?
- Which value would you change?
- What does the error message point to?
- Can you test just one part?
- What changed after your last edit?
- How would you explain this line to someone else?

Avoid taking over the keyboard unless the learner asks for direct help or an accessibility need makes it useful.

## If the session runs short

Finish at a working point. Ask the learner to say what they would try next.

Do not introduce a new concept during the final few minutes just to complete a lesson.

## If the session runs long

Use the exercise page, bonus challenge, bug hunt or a learner-designed variation.

Extra time should deepen the current idea rather than introduce several future concepts early.
