# M3.9 – Build a mini-game! 🎮

## 🎯 Mission

Put the pieces together: controls, a target, score, monster, lives, GAME OVER, and feedback.

This is a bigger program. You do **not** need to type everything again.

## 🧩 Build in small pieces

Test in this order:

1. Does the window open?
2. Can the player move?
3. Can you catch the target?
4. Does the score increase?
5. Does the monster move?
6. Do you lose a life when caught?
7. Does the game stop at zero lives?

## 💻 Complete example

Use `examples/m3-mini-game.py` when you need a working starting point.

Run it, play a few rounds, then find the variables, movement functions, catch test, monster test, and GAME OVER function.

You do not need to understand every line before you can change the program.

## 🔧 Change one thing

Start with one small change: player step, monster speed, lives, colours, title, or points per target. Run and test before changing something else.

## ⭐ Make a variant

Give your version its own name, theme, and at least one changed game rule.

## 🧪 Playtest

Let someone else play. Ask what was easy to understand, what was too hard or easy, and what was fun. Improve one thing.

## 🐞 Bug hunt

When a change breaks something, look at the last small change first.

**Change → run → test.**

## 🧠 What you learned

- bigger programs can be built from small pieces
- you can test one piece at a time
- movement, score, lives, and enemies can work together
